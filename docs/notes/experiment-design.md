# 무인운반차 배차 트리 실험 설계

**다섯 사람이 각자 차량 대수와 완성된 트리 전체를 결정한다.** 사람마다 더 깊게 볼 계열이나 가설을 정하고, 모든 노드와 임계값, 우선 방향을 직접 선택한다. 완성 후보는 개인 폴더에 넣고, AI(Artificial Intelligence, 인공지능)가 검사·재평가·중복 확인·비교를 맡는다. 다른 사람의 중간 산출물을 기다릴 필요가 없다.

기존 18·19·20대 팀 후보는 비교 기준으로만 쓰고, 기존 민감도 분석으로 새 탐색 범위를 미리 결정하지 않는다. [회의용 로드맵](https://ie325-agv-team14-experiment-roadmap.jsm0308.chatgpt.site)에서 다섯 사람의 탐색 초점과 공통 제약을 볼 수 있다.

## 공통 조건과 변수 관계

[과제 규칙](../../README.md#확정된-과제-규칙)대로 통로 방향, 차량 이동과 교차로 처리, 요청 생성 조건, 초기 차량 배치 규칙을 고정한다. 설계에서 바꾸는 것은 차량 대수와 배차 트리다. 각 노드는 값이 임계값 이하(≤)면 `lo`, 초과(>)면 `hi`로 보낸다. `min`은 이하 그룹, `max`는 초과 그룹을 우선한다. 양쪽 후보가 같은 그룹이면 해당 자식에서 비교를 이어가고, 끝까지 같으면 빈 차 거리 → 요청 순번 → 차량 번호를 따른다. 트리는 루트 번호 1에서 시작한다. 규칙 노드는 1~9개, 깊이는 최대 5이며 한 경로에서 같은 변수를 재사용할 수 없다. 자식 번호 0은 비교 종료다.

`de`는 차량 위치부터 요청 출발지까지의 빈 차 거리이고, `dl`은 그 요청의 적재 거리다. `w`는 요청 발생부터 현재 배차 판단까지 기다린 시간이다. 채점상 픽업 대기에는 **배정 후 차량이 오기까지의 시간**도 들어가므로 `de`와 `w`를 서로 다른 기준으로 본다. `qo`는 그 순간 출발지별 미배정 건수다. 같은 출발지의 요청끼리는 그 값이 같고, 한 건을 배정한 직후 바뀔 수 있다.

현재 케이스에서 긴급 요청은 모두 `SORT → SHIP`이고 적재 거리가 25m다. 따라서 **긴급 가지의 `dl` 비교와 `dl > 25` 가지의 `urg` 비교는 분기를 만들 수 없다.** 25m인 일반 요청도 있으므로 `dl ≤ 25`에서 `urg`를 보는 것은 의미가 있다. 이 관계는 [케이스 데이터](../../docs/case.json)에서 확정된다. 또 긴급 요청은 출발지가 모두 `SORT`라 한 배차 판단 안에서는 `qo`가 같다. 그래도 `SORT`에 쌓인 건수는 판단 시점마다 달라져 `qo`가 서로 다른 자식 규칙을 선택하게 만들 수 있다. **한 시점에 후보끼리 값이 같은 경우와, 어떤 시점에도 분기가 바뀌지 않는 경우를 구분한다.**

매 시드는 3,000분, 준비 구간은 300분이다. 공식 비용과 시뮬레이터의 집계 규칙을 그대로 쓴다. 비용은 차량 고정비, 전체 평균 픽업 대기 비용, 긴급 픽업 대기 95백분위수 비용의 합이다. 전체 미배정 큐가 중간에 300건을 넘거나 종료 시 30건을 넘으면 반려한다. 기존 탐색의 별도 혼잡 조기 중단값은 쓰지 않는다.

## 1. 다섯 계열에서 서로 다른 시작점 15개를 만든다

de Koster 외는 거리 기반 배차가 평균 대기를 줄이면서도 오래 기다리는 요청을 남길 수 있음을 보였다. 일정 시간 넘게 기다린 요청에 우선권을 주는 아이디어를 세 형태로 비교한다. **거리만 우선**, **오래 기다린 요청이 거리 우선을 넘어설 수 있음**, **먼 거리 그룹 안에서만 오래 기다린 요청 우선**이다. 마지막 형태에서는 먼 곳의 오래된 요청이 가까운 그룹을 추월할 수 없다. 같은 변수를 써도 노드 위치가 정책을 바꾼다는 뜻이다. 논문에서 본 최대 대기와 과제의 긴급 대기 95백분위수는 따로 기록한다. [de Koster 외, 2004](https://doi.org/10.1016/j.jom.2004.05.006) · [공동저자 Le-Anh의 학위논문 3.2.3절](https://repub.eur.nl/pub/6554/EPS2005051LIS_9058920798_TUANLEANH.pdf)

Bilge 외가 빈 차 이동시간과 출발지 버퍼를 함께 본 것에서, **가까운 차량–요청 짝 사이에서만 적체를 볼지, 적체를 거리보다 앞세울지**를 비교한다. Klein과 Kim의 부서별 대기 차이를 참고해 전체 평균 외에 어느 출발지의 요청이 밀리는지도 본다. 논문들의 가중합 규칙은 과제의 트리 형식에 맞춰 우선순위가 다른 구조로 옮긴다. [Bilge 외, 2006](https://doi.org/10.1016/j.ijpe.2004.10.004) · [Klein & Kim, 1996](https://doi.org/10.1080/00207549608904893)

| 계열 | 실험 질문 | 우선 비교 |
| --- | --- | --- |
| D · 빈 차 거리 | 가까운 차량을 먼저 보내면서 어느 가지에 예외를 둘까? | D0–D1은 가까운 그룹 내 적체 우선, D1–D2는 먼 그룹 내부의 오래된 요청 우선 |
| W · 오래된 요청 | 일정 시간을 넘기면 거리 우선을 넘어서는 편이 나을까? | D0–W0은 대기 예외 하나의 효과, D1–W2는 거리·적체 방식에 전역 대기 예외를 추가한 효과 |
| Q · 출발지 적체 | 요청이 쌓인 출발지를 거리보다 먼저 볼까? | D1–Q0은 가까운 쪽에서만 적체 우선과 전역 적체 우선의 비교 |
| U · 긴급 | 긴급을 첫 기준으로 두면 비용 대비 긴급 대기가 더 줄까? | D0–U0은 긴급 우선, U0–U1은 긴급 그룹에서 대기 예외의 효과 |
| L · 적재 거리 | 짧은 운반을 먼저 끝내는 이득이 장거리 요청의 추가 대기를 상쇄할까? | D0–L0은 적재 거리 우선, L1–L2는 장거리 그룹의 적체 예외 |

아래 식에서 `변수(방향,임계값)[lo,hi]`는 규칙 노드다. `-`와 자식 생략은 비교 종료다. 가지 배치와 변수 위치가 같으면 같은 골격으로 본다. 우선 방향과 임계값의 차이는 따로 기록한다.

~~~text
D0 = de(min,205)
D1 = de(min,50)[qo(max,1),-]
D2 = de(min,50)[qo(max,1),w(max,4)]

W0 = w(max,4)
W1 = w(max,4)[-,urg(max,0.5)]
W2 = w(max,4)[de(min,50)[qo(max,1),-],-]

Q0 = qo(max,1)
Q1 = qo(max,1)[-,w(max,4)]
Q2 = qo(max,1)[dl(min,50),w(max,4)]

U0 = urg(max,0.5)
U1 = urg(max,0.5)[-,w(max,4)]
U2 = urg(max,0.5)[qo(max,1),w(max,4)]

L0 = dl(min,50)
L1 = dl(min,50)[urg(max,0.5),-]
L2 = dl(min,50)[urg(max,0.5),qo(max,1)]
~~~

계열 가설은 표의 짝을 **같은 대수·시드에서** 비교한다. 둘 다 대기 규칙이 있으면 같은 경계값끼리 먼저 본다. 이 비교에서 관측한 출발지별 대기 차이는 구조를 설명하는 데 쓰고, 여러 대수에서 가장 좋은 값만 골라 한 규칙의 효과로 보고하지 않는다.

D0에서는 가능한 빈 차 거리 전부가 205m 이하라 트리 비교가 동점이다. 이후 기본 비교가 실제 빈 차 거리로 고르므로 **순수 거리 기준선**이 된다. W0는 4분 *초과* 그룹에 우선권을 주고, 그 그룹 안에서는 가까운 차량부터 고른다. 오래 기다린 순으로 전체를 정렬하는 규칙은 아니다. W2는 오래 기다린 그룹을 먼저 보고, 나머지는 D1처럼 처리한다. 논문의 대기 예외와 현재 과제의 거리·대기열 관계를 함께 시험하는 구조다.

## 2. 다섯 사람은 탐색을 집중할 곳을 나눈다

아래 분담은 예시다. 루트 변수로 나누면 각 구조가 무엇을 먼저 보는지 비교하기 쉽다. 루트 대신 “멀리 있는 오래된 요청 구제”처럼 **가지의 위치나 변수 조합에 관한 가설**을 맡아도 된다.

| 자리 | 깊게 볼 계열 예시 | 완성 트리에서 비교할 것 |
| --- | --- | --- |
| 1 | 빈 차 거리 D | 가까운 그룹의 적체 예외와 먼 그룹의 장기 대기 예외 |
| 2 | 긴급 U | 긴급 우선과 긴급 그룹 내 대기시간 재분기 |
| 3 | 오래된 요청 W | 장기 대기를 전역에서 우선하는 방식과 특정 가지에서만 우선하는 방식 |
| 4 | 출발지 적체 Q | 적체 우선과 거리·대기시간을 조건부로 결합하는 방식 |
| 5 | 적재 거리 L | 짧은 적재 이동 우선과 장거리 그룹의 적체 예외 |

각자는 기본 계열에서 구조가 다른 시작점 3개 이상을 잡는다. 위 15개 예시를 써도 되고 새 가설로 만들어도 된다. 임계값만 다른 트리는 같은 구조로 본다. 같은 변수를 쓴다고 같은 정책인 것은 아니다. 예를 들어 대기시간이 루트에 있으면 오래 기다린 요청이 거리 우선을 넘어설 수 있지만, 먼 거리 가지 안에만 있으면 그 그룹 안에서만 순서를 바꾼다. 다른 루트와 교차 계열도 탐색할 수 있으며 출발 가설과 최종 루트를 모두 기록한다.

## 3. 각자가 대수와 트리를 함께 탐색한다

- **대수** 첫 주 제안은 1~15대 홀수, 16~22대 전부, 23~30대 홀수로 총 19대수다. 16~22대는 공개 기준 후보 18~20대 주변의 비교 구간이다. 조사한 대수 사이에서 반려 여부가 바뀌거나 무반려인 같은 트리의 최저 비용과 10점 이내이면 조사하지 않은 인접 대수도 확인한다. 29대가 유망하거나 상한을 점검할 때는 30대를 추가한다.
- **구조:** 임계값 변경 → 규칙·우선 방향 교체 → 하위 가지 변경을 기본 순서로 삼을 수 있다. 개선되면 작은 변경부터 다시 보고, 정체하면 다른 시작 구조로 옮긴다. 개인별 탐색 방식은 자유다. 노드가 서로 영향을 줄 때는 각각을 바꾼 후보와 둘을 함께 바꾼 후보를 같은 입력에서 비교한다.
- **임계값:** de는 0·25·50·65·90·115·140·155·180m, dl은 25·50·65·90m가 분기를 만드는 경계다. qo는 1·2·3·5·8건, w는 0.5·1·2·4·8·16·32분부터 보고, 도달 후보의 로그를 근거로 필요한 구간만 좁힌다. urg 경계는 0.5다. 새 answer.csv는 de·dl의 실제 거리, qo의 정수 경계로 통일한다. 예컨대 de 70은 65로 쓴다. w는 연속값이므로 실제 시험한 소수값을 보존한다.
- **비교 예산:** 간단한 예비 비교에는 공통 5시드(1001~1005)를 쓴다. 첫 대수 조사는 공통 8시드, 이후 탐색 비교는 공통 16시드다. 기본 비교 예산은 사람당·대수당 서로 다른 완성 후보 최대 360개로 두고 90·180·270·360개 시점의 최선값을 남긴다. 추가 실행은 별도 탐색으로 표시한다. 비교할 수 있는 것은 주어진 예산 안에서 방문한 후보들이다.

## 4. 개인 폴더에 후보와 결과를 올린다

기존 팀원 폴더를 사용한다. 새 폴더나 이름을 배정할 필요는 없다.

~~~text
solutions/<기존 개인 폴더>/
  <후보ID>.csv    대수와 완성 트리 전체를 담은 공식 제출 파일
  <후보ID>.md     출발 가설, 이전 후보에서 바꾼 점, 실행 조건과 결과 위치
~~~

후보 설명에는 작성자 또는 폴더, 출발 계열·최종 루트, 대수, 엔진 커밋, 사용한 시드와 평가 횟수를 적는다. 최소한 완성 CSV(Comma-Separated Values, 쉼표로 구분한 값 파일)와 가설을 올리면 공통 엔진으로 재평가할 수 있다. 개인 최선과 구조가 다른 유망 후보를 함께 남긴다.

팀원은 개인 폴더에서 후보별 시드, 비용, 반려 여부를 기록한다. 비교할 후보는 같은 대수와 시드로 평가한다.

### 3주 탐색 현황을 읽는 법

1주차에는 거리 우선(de), 장기 대기 우선(w), 긴급 우선(urg) 대표 트리 3개로 대수를 먼저 훑고 살아남은 대수에서 시작 골격 15개를 비교한다. 2주차에는 가지·방향·임계값을 좁히고, 3주차에는 고정한 후보를 별도 시드와 공식 웹에서 확인한다. 회의 웹은 골격 15개 × 기본 대수 19개를 펼쳐 보여 준다. 각 칸의 숫자는 페이지에 등록된 후보 수다. 이 285칸은 계획을 나눈 단위이며 한 사람의 평가 예산 360회와 단위가 다르다.

착수 전 팀원과 에이전트는 해당 칸의 GitHub 이슈를 확인한다. 제목에 보드의 EXP 식별자를 넣고 담당·브랜치·예정 규칙·임계값·시드·엔진 커밋을 남긴다. 이미 평가한 동일 후보는 엔진·케이스·시드별 결과가 일치하면 재사용한다. 진행 중 상태는 연결된 이슈에서 확인한다.

### 월요일 회의에서 제안할 파트

곽민재가 공개한 18·19·20대 후보는 모두 `de(min,65)`가 루트다. 가까운 가지는 `qo`, 먼 가지는 `dl`부터 본다. 19대 최종안은 19대 후보의 복사본이다. 공개 후보가 보여 주는 출발점은 거리 우선이며, 곽민재가 현재 따로 실험 중인 계열은 확인할 수 없다.

내 파트는 **장기 대기의 전역 예외**를 제안한다. 같은 대수·시드에서 `D0`(거리), `D1`(거리와 가까운 가지 적체), `D2`(D1의 먼 가지 안에서만 장기 대기 우선), `W2`(D1 앞에 전역 대기 예외)를 비교한다. `D2`와 `W2`에 같은 `w` 기준을 쓰면 장기 대기를 어디에 둘지 비교할 수 있다. 처음에는 `1·2·4·8분`을 사용하고, 공통 대수 조사에서 살아남은 대수에서 반려·총비용·긴급 대기 95백분위수로 판정한다. 이후 상위 구조의 인접 대수와 `w`를 좁혀 본다. 나머지 세 명의 초점은 회의에서 정한다.


## 5. 검증과 진행 상태

| 목적 | 공통 시드 | 판정 |
| --- | --- | --- |
| 첫 대수 조사 | 1001–1008 | 반려 여부와 시드별 비용 기록 |
| 개인 탐색 비교 | 1001–1016 | 반려를 먼저 확인하고 무반려 후보의 시드별 비용 차이를 비교 |
| 취합 후 선별 | 2001–2032 | 사람별 새 후보 최대 2개와 기존 3개, 중복 제거 전 최대 13개 |
| 최종 확인 | 3001–3064 | 새 후보 최대 3개와 기존 기준 1개를 먼저 고정한 뒤 평가 |

반려된 후보는 성공한 시드의 평균만으로 위로 올리지 않는다. 총비용과 전체 평균·긴급 95백분위수 픽업 대기, 최대·종료 미배정 큐를 함께 본다. 탐색용 5·8·16시드는 1001에서 시작하는 중첩 묶음이다. 16은 예산상 정한 반복 수다. 두 후보의 같은 시드 비용 차이가 작거나 반려가 엇갈리면 순위를 유보하고 새 32시드에서 확인한다. 대표 실행에는 요청 발생·배정·픽업·하차 시각과 출발지별 대기열을 기록한다. 최종 시드를 보고 후보를 바꾸면 새 검증 시드가 필요하다. 최종 새 후보 최대 2개와 기존 기준 1개는 교수님 웹에서 동일 CSV로 비교한다.

- **확인 완료:** 고정 맵과 공식 분기·노드 제약, 시작 구조 15개와 임계값 변형 39개의 로컬 정책 검사. [시드 11~15 요청 파일](../../data/scenarios/)과 [시뮬레이터 검증 기록](../../src/simulator-validation.md)은 이미 저장했다. 이 시드 파일은 재현용이며 위 새 탐색·검증 시드와는 별개다.
- **남은 작업:** 첫 회의에서 각자 더 볼 가설을 정한다. 현 시점에 공개된 기준 후보는 곽민재 폴더에 있다.

탐색에는 다른 시작점에서 재시작하고 작은 변경에서 큰 변경으로 넓히는 방법을 사용할 수 있다. 비교에는 공통 난수를 사용한다. ## 거시 설계 마감과 다음 회의

거리(de), 장기 대기(w), 출발지 적체(qo), 긴급(urg), 적재 거리(dl)에서 각각 시작하고 대수는 전원이 함께 본다. 예비 비교는 같은 대수에서 트리를 바꿔 공통 5시드로 보고, 대수 조사는 대표 트리를 고정하고 차량 수를 바꿔 앞의 5개를 포함한 8시드로 본다. 기본 19대수는 같은 트리·시드 기준으로 전수 조사보다 실행 횟수가 약 36.7% 적다.

다음 회의에서는 각 담당자가 루트의 이하·초과 가지에서 어떤 변수를 먼저 볼지 정한다. 각자 기준 트리 하나와 2층 규칙 하나를 바꾼 트리를 준비하고, 같은 대수·시드에서 확인할 가설과 평가 지표를 적는다. [회의 웹의 관계표](https://ie325-agv-team14-experiment-roadmap.jsm0308.chatgpt.site/#relations), [탐색 현황판](../experiment/index.html#coverage), [기존 후보 원본](../../solutions/KMJ/)을 함께 참고한다.
