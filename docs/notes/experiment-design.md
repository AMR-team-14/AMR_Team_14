# 무인운반차 배차 트리 실험 설계

AGV(Automated Guided Vehicle, 무인운반차) **대수와 배차 트리**를 함께 정해 시간당 운영비를 줄인다. 다섯 사람이 서로 다른 루트 변수에서 출발해 각자 완성 트리와 대수를 정하고, 같은 시드·예산으로 비교한다.

**지식으로 탐색 공간을 줄이고, 트리를 한 층씩 선택적으로 키우며, 시뮬레이션 결과로 다음 확장을 정한다.**

## 0. 문서 구조

이 문서는 설계를 두 축으로 나눈다.

- **범위:** **거시 설계**는 대수·시드·예산·분담·검증처럼 모든 사람이 공유하는 실험 틀이다. **미시 설계**는 한 사람이 트리를 한 층씩 키우는 방법이다.
- **근거:** **논리 기반 설계**는 시뮬레이션 없이 케이스 구조와 규칙만으로 판단한다. **실험 기반 설계**는 시뮬레이션 결과로 판단한다.

| | 논리 기반 (시뮬레이션 없이) | 실험 기반 (시뮬레이션으로) |
| --- | --- | --- |
| **거시** | 루트 분담, 대수 후보 범위, 시드 단계 구분 ([6](#6-루트-계열과-초기-가설), [8.4](#84-분담)) | 대수 조사, 단계별 시드 평가, 최종 검증 ([8](#8-거시-실험), [11](#11-검증-절차와-기록)) |
| **미시** | 변수 관계, 논리 축소, 하위 규칙 가설, `qo` 부하 분석 ([4](#4-케이스에서-확정되는-변수-관계)~[7](#7-qo-부하-분석)) | 층별 확장, 짝 비교, 임계값 탐색, 실험 축소 ([9](#9-미시-실험--선택적-층별-확장), [10](#10-실험-축소와-진단-지표)) |

**논리 축소와 실험 축소.** 이전 초안의 “정적 축소”는 시뮬레이션 없이 증명으로 후보를 지우는 것이라 논리 기반 설계의 일부이고, “동적 축소”는 배차 로그를 관찰해 지우는 것이라 실험 기반 설계의 일부다. 둘이 1:1로 대응하므로 이 문서는 **논리 축소 / 실험 축소**만 쓴다. `qo`처럼 시간에 따라 값이 바뀌는 변수를 “동적 변수”라 부르는 것과 섞이지 않게 하려는 이유도 있다.

| 방법 | 이 프로젝트에서 맡는 일 |
| --- | --- |
| Knowledge-Guided Search(지식 유도 탐색) | 케이스 구조와 변수 관계로 후보를 미리 제거 → 논리 기반 |
| Sequential Experimental Design(순차적 실험 설계) | 이전 결과로 다음 실험과 시드 예산을 정함 → 실험 기반 |
| Simulation-Based Optimization(시뮬레이션 기반 최적화) | 시뮬레이터가 돌려준 운영비로 정책을 평가 → 실험 기반 |

매번 최고 후보 하나만 키우면 국소해에 갇히므로 유망한 가지 여러 개를 함께 유지하는 **선택적 층별 확장(Selective Level-wise Growth)** 을 쓴다. 팀이 정의한 운영 방식이며 특정 논문의 알고리즘을 그대로 구현한 것은 아니다.

# I. 공통 기반

## 1. 문제 정의

$$
\min_{n,\mathcal T}\ \mathbb E_s[C_s(n,\mathcal T)],\qquad
C_s = 15n + 102.24\,\overline W_s + 100\,U_{95,s}
$$

| 기호 | 의미 |
| --- | --- |
| $n$ | 차량 대수, 정수 1~30 |
| $\mathcal T$ | 배차 우선순위를 정하는 이진 트리 |
| $\overline W_s$ | 시드 $s$의 전체 요청 평균 픽업 대기(분) |
| $U_{95,s}$ | 시드 $s$의 긴급 요청 픽업 대기 95백분위수(분) |
| $102.24$ | 대기 비용 계수 0.6 × 시간당 요청 170.4건(기본 물동량 284건 × 생성 비율 0.6) |

기대값은 공통 시드 집합 $S$로 추정한다. 모든 평가 시드가 반려 없이 끝나야 비용을 비교 지표로 쓴다. 비용이 낮아도 반려된 후보는 통과 후보보다 앞설 수 없다.

**로컬 점수와 공식 점수는 다르다.**

- **집계:** 짝 비교에는 시드별 비용 $C_s$를 쓴다(9.2절). 로컬 `--eval-json`의 `average`는 $C_s$의 산술평균이다. 팀원 기록(`jinhong-experiments` 브랜치 README)에 따르면 공식 채점은 여러 시드의 대기시간을 모아 $\overline W$와 $U_{95}$를 한 번 계산한다. 95백분위수는 비선형이라 두 값이 다를 수 있다.
- **난수:** 시드 11은 공식 배차 로그를 복원한다. 12 이후 시드는 공식 웹과 다른 난수 흐름으로 로컬에서 생성한다([KMJ 보고서 3.1절](../../solutions/KMJ/final_agv_report.md)).
- 그래서 로컬 결과는 **같은 조건의 후보 간 상대 비교**에 쓰고, 공식 점수는 웹에서 따로 확인한다. 기록에는 집계 방식을 함께 적는다.

## 2. 필수 제약

팀원 재량으로 바꿀 수 없다. 에이전트가 자동 검사한다. [과제 규칙](../../README.md#확정된-과제-규칙)

| 구분 | 제약 |
| --- | --- |
| 통로망 | 공식 케이스의 26개 노드·29개 구간과 고정 일방통행 방향 |
| 이동 | 지정 경로, 차량 이동, 교차로 처리 규칙 그대로 |
| 요청 | 공식 생성률, 이동 흐름 9개, 긴급 정의(`SHIP`행) 유지 |
| 초기 상태 | 차량 초기 배치와 시뮬레이터 초기화 규칙 유지 |
| 차량 대수 | $1\le n\le 30$, 정수 |
| 트리 | 규칙 노드 $1\le N(\mathcal T)\le 9$, 루트 번호 1, 깊이 최대 5 |
| 변수 재사용 | 한 루트–말단 경로에서 같은 변수 사용 불가. 다른 가지에서는 가능 |
| 분기 | 값 ≤ 임계값이면 `lo`, > 이면 `hi`. 자식 `0`은 비교 종료 |
| 우선 방향 | `min`은 이하 그룹, `max`는 초과 그룹 우선 |
| 시뮬레이션 | 시드당 3,000분, 준비 구간 300분. 기존 탐색의 별도 혼잡 조기 중단값은 쓰지 않음 |
| 반려 | 실행 중 전체 미배정 큐 300건 초과 또는 종료 시 30건 초과(시드별 판정) |
| 평가 | 공식 비용함수와 공식 CSV 형식 |

$$
n\in\{1,\dots,30\},\quad 1\le N(\mathcal T)\le 9,\quad \operatorname{depth}(\mathcal T)\le 5,\quad
f_i\ne f_j\ (\text{같은 경로}),\quad \max_t Q_s(t)\le 300,\ Q_s(3000)\le 30
$$

**CSV가 유효하다는 것과 그 정책이 반려 없이 운영된다는 것은 다르다.** 정적 검사와 시뮬레이션 평가는 따로 보고한다.

## 3. 배차 변수와 엔진의 비교 방식

배차 대상은 요청 하나가 아니라 **빈 차량 $a$와 대기 요청 $r$의 조합 $(a,r)$** 이다.

| 변수 | 정의 | 케이스의 값 | 초기 탐색 |
| --- | --- | --- | --- |
| `de` | 빈 차 위치 → 요청 출발지 거리 | 0, 25, 50, 65, 90, 115, 140, 155, 180, 205m | 경계 0~180m 전부 |
| `dl` | 요청 출발지 → 목적지 거리 | 25, 50, 65, 90, 115m | 경계 25, 50, 65, 90m 전부 |
| `w` | 요청 발생부터 배차 판단까지 경과(분) | 0~3,000분 연속값 | 0.5·1·2·4·8·16·32분에서 시작해 유망 구간 세분 |
| `qo` | 같은 출발지의 현재 미배정 건수(해당 요청 포함) | 1~300 | 부하·큐 진단 후 결정(7절, 9.4절) |
| `urg` | 긴급 여부 | 0, 1 | 임계값 0.5 |

$$
de=d_{\text{directed}}(x_a(t),o_r),\quad dl=d_{\text{directed}}(o_r,d_r),\quad w=t-t_r^{arr},\quad qo=\textstyle\sum_{j:o_j=o_r}\mathbf 1[j\ \text{미배정}]
$$

CSV에는 `de`·`dl`은 실제 거리값, `qo`는 정수 경계로 쓴다(예: `de` 70은 65로 작성). `w`는 연속값이므로 시험한 소수값을 그대로 보존한다.

`w`와 채점용 픽업 대기는 다르다. 오래 기다린 요청에 먼 차를 보내면 `w`는 해소돼도 픽업 대기는 길어질 수 있다.

$$
W_r^{pickup}=\underbrace{t_r^{dispatch}-t_r^{arr}}_{w}+\underbrace{t_r^{pickup}-t_r^{dispatch}}_{\text{배정 후 이동}}
$$

**엔진의 비교 방식** (`src/simulator.cpp`)

- 각 조합은 트리를 따라 내려가며 노드마다 “우선 가지면 0, 아니면 1”을 기록하고, 이 비트열을 사전순으로 비교한다. 두 조합이 처음 갈라지는 노드에서 우선 가지 쪽이 이긴다.
- 끝까지 같으면 **최소 `de` → 최소 요청 순번 → 최소 차량 번호** 순으로 고른다.
- 비교 후보는 압축한다. 같은 위치의 빈 차는 번호가 가장 작은 한 대만 남긴다. 요청은 흐름(출발지–목적지)마다 가장 오래된 요청만 남기고, 트리에 `w(min)` 노드가 있으면 그 임계값 경계에 걸친 요청을 흐름마다 추가한다. 같은 흐름 안의 요청은 `de`·`dl`·`qo`·`urg`가 같고 `w`만 다르므로 이 압축은 결과를 바꾸지 않는다.

# II. 논리 기반 설계

시뮬레이션 없이 케이스 데이터·과제 규칙·엔진 동작만으로 판단하는 부분이다.

## 4. 케이스에서 확정되는 변수 관계

[케이스 데이터](../../docs/case.json)에서 아래 관계가 확정된다.

- 긴급 요청은 모두 `SORT → SHIP` 한 흐름이고 적재 거리는 25m다. `SORT`에서 출발하는 흐름은 이것뿐이므로 **`urg=1`과 “출발지가 SORT”는 같은 조건**이다.
- 따라서 긴급 그룹의 `dl`은 항상 25m이고, 같은 판단 시점의 긴급 후보는 `qo`가 모두 같다(SORT 큐 길이). SORT 큐 길이는 시점마다 달라 `qo`가 서로 다른 자식 규칙을 고르게 만들 수 있으므로, **한 시점에 후보끼리 값이 같은 경우와 어떤 시점에도 분기가 바뀌지 않는 경우를 구분한다.**
- 25m인 일반 요청도 있으므로 `dl≤25` 가지의 `urg` 노드는 의미가 있다.

| 관계 | 배차 순간의 예시 | 설계에 적용할 점 |
| --- | --- | --- |
| `urg` × `dl` | 긴급은 모두 25m, 일반 요청 중에도 25m가 있다 | 긴급 가지 아래에서는 `de`나 `w`를 본다. 적재 거리 담당은 25m 그룹 안에 `urg`를 넣어 긴급을 따로 우선할 수 있다 |
| `urg` × `qo` | 10시에 SORT 미배정 6건이면 두 긴급 요청 모두 `qo=6`, 11시에 1건이면 `qo=1` | 긴급 가지의 `qo`는 같은 순간의 긴급 요청을 가르지 못한다. 대신 시점별로 다른 자식 규칙을 고르게 할 수 있다 |
| `de` × `w` | A는 25m·1분, B는 90m·10분. `de≤50` 우선이면 A, `w>4` 우선이면 B | 장기 대기 예외를 루트에 둘 때와 먼 거리 가지에만 둘 때를 비교 |
| `qo` × `w` · `de` × `qo` | A 출발지는 방금 온 5건, B는 12분 기다린 1건. 적체 우선은 A, 장기 대기 우선은 B | `qo`를 루트에 둘지 가까운 그룹 안에서만 쓸지 비교. 한 건만 오래 밀린 출발지가 있는지 확인 |
| 대수 × 전 변수 | 적재 운반 중인 차량은 다음 배차에서 빠진다. 차가 늘면 가까운 빈 차가 생기지만 고정비와 교차로 대기도 바뀐다 | 같은 트리를 인접 대수에서 다시 비교하고 `w`·`qo` 경계를 넘은 빈도를 본다 |

## 5. 논리 축소

노드 9개 이하·깊이 5 이하인 트리 형태는 **1,813개**다(변수·방향·임계값 배치 전). 루트의 두 자식을 모두 채우도록 강제하면 1,302개로 줄지만 좋은 정책을 배제할 수 있어 **필수 제약으로 두지 않는다.** `lo`/`hi`를 뒤집은 거울형은 다른 정책이므로 합치지 않는다.

| 검사 | 조건 | 조치 |
| --- | --- | --- |
| 경로 중복 | 같은 경로에 같은 $f$가 두 번 | 후보 무효 |
| 상수 분기 | 도달 가능한 모든 후보가 $f\le\theta$ | 노드를 유일한 도달 자식으로 치환 |
| 불가능 분기 | 도달 가능한 모든 후보가 $f>\theta$ | 반대 자식으로 치환 |
| 긴급의 적재 거리 | $urg=1\Rightarrow dl=25$ | 긴급 가지의 `dl` 노드 제거 |
| 장거리의 긴급 여부 | $dl>25\Rightarrow urg=0$ | 해당 가지의 `urg` 노드 제거 |
| 기본 규칙 중복 | 말단 `de(min,θ)`의 두 자식이 모두 0 | 노드 제거(기본 최근접 선택과 같은 결과) |
| 이산 임계값 동등 | 다른 임계값이 같은 값 집합을 나눔 | 대표값 하나만 유지 |
| 노드 한도 | $N+1>9$ 또는 추가 후 깊이 > 5 | 확장 금지 |

- 상수 분기 제거는 한쪽 자식만 연결해도 정책이 같다는 것이 **증명될 때만** 적용한다. 긴급 가지의 `qo`처럼 시점마다 값이 바뀌는 노드는 일괄 제거하지 않는다.
- 내부 노드인 `de(min,θ)`는 두 거리 그룹에 다른 하위 규칙을 붙이므로 유지할 수 있다. `de(max,θ)`는 최근접과 반대 우선권을 주므로 따로 검토한다.
- **추가 노드는 기본 동점 규칙과 다른 선택을 만들 가능성이 있어야 한다.**

## 6. 루트 계열과 초기 가설

루트는 담당 변수로 고정한다. 하위 트리의 노드 수·깊이·구성·임계값은 일률적으로 제한하지 않는다.

| 계열 | 핵심 질문 | 우선 검토할 하위 규칙 | 주의 |
| --- | --- | --- | --- |
| D · `de` | 최근접 우선에 어떤 예외가 필요한가? | 가까운 그룹에 `qo`·`urg`, 먼 그룹에 `w` | 멀다는 이유로 요청을 소외시키지 않기 |
| W · `w` | 오래 기다린 요청을 언제 거리보다 앞세울까? | 짧은 대기에 `qo`, 긴 대기에 `urg` | 오래된 요청이 멀면 픽업 이동 증가 |
| Q · `qo` | 적체 해소를 먼저 하면 총비용이 줄까? | 적체 수준별 `w`·`urg`, 저적체에서 `de` | 저부하 출발지의 장기 소외 |
| U · `urg` | 긴급을 항상 먼저 처리해야 하나? | 일반 그룹에서 `qo`·`dl`·`w` | 긴급 루트 우선이면 오래된 일반 요청이 긴급을 추월하지 못함 |
| L · `dl` | 짧은 운반 우선이 처리 효율을 높이나? | 짧은 운반에 `urg`, 긴 운반에 `w`·`qo` | 긴 운반 소외, 긴급=짧은 거리 상관 |

- **D:** `de(min,205)`는 모든 후보를 동점으로 만들어 기본 최근접에 맡기는 순수 거리 기준선이다. 모든 비교에 포함한다.
- **W:** `w(max,4)`는 4분 초과 그룹을 우선할 뿐, 그 안에서 오래 기다린 순으로 정렬하지 않는다(그룹 안은 최근접).
- **Q:** `qo`는 정책이 만들어 내는 값이다. 요청 발생률만 보고 임계값을 확정하지 않는다.
- **U:** `w(max)`만 쓰는 트리에서는 흐름마다 가장 오래된 요청이 대표 후보이므로 긴급 그룹의 추가 `w(max)`는 중복일 수 있다. 긴급 그룹의 `dl`은 25m 고정이고 `qo`는 같은 시점에 동일하다. 일반 그룹 확장에 예산을 더 배분하는 것이 초기 가설이다.
- **L:** 모든 긴급 요청이 `dl(min,θ)`의 짧은 그룹에 들어간다. 짧은 운반 우선 효과와 긴급 보호 효과를 구분해 분석한다.

**문헌에서 가져온 가설.** de Koster 외는 거리 기반 배차가 평균 대기를 줄이면서도 오래 기다리는 요청을 남길 수 있음을 보였다. 그래서 **거리만 우선**, **오래 기다린 요청이 거리 우선을 넘어설 수 있음**, **먼 거리 그룹 안에서만 오래 기다린 요청 우선**을 비교한다. 같은 변수를 써도 노드 위치가 정책을 바꾼다. Bilge 외가 빈 차 이동시간과 출발지 버퍼를 함께 본 것에서 **가까운 짝 사이에서만 적체를 볼지, 적체를 거리보다 앞세울지**를 비교하고, Klein과 Kim의 부서별 대기 차이를 참고해 어느 출발지의 요청이 밀리는지도 본다. 논문들의 가중합 규칙은 과제의 트리 형식에 맞춰 우선순위가 다른 구조로 옮긴다. 논문의 최대 대기와 과제의 긴급 95백분위수는 따로 기록한다.

**참고 골격 15개.** 아래 식에서 `변수(방향,임계값)[lo,hi]`는 규칙 노드, `-`와 자식 생략은 비교 종료다. 계열별 3개를 의무화하지 않는다. 루트 기준선에서 출발해 필요한 구조를 더하고, 이 골격은 비교 후보로 쓴다.

~~~text
D0 = de(min,205)          D1 = de(min,50)[qo(max,1),-]       D2 = de(min,50)[qo(max,1),w(max,4)]
W0 = w(max,4)             W1 = w(max,4)[-,urg(max,0.5)]      W2 = w(max,4)[de(min,50)[qo(max,1),-],-]
Q0 = qo(max,1)            Q1 = qo(max,1)[-,w(max,4)]         Q2 = qo(max,1)[dl(min,50),w(max,4)]
U0 = urg(max,0.5)         U1 = urg(max,0.5)[-,w(max,4)]      U2 = urg(max,0.5)[qo(max,1),w(max,4)]
L0 = dl(min,50)           L1 = dl(min,50)[urg(max,0.5),-]    L2 = dl(min,50)[urg(max,0.5),qo(max,1)]
~~~

| 비교 짝 | 확인할 것 |
| --- | --- |
| D0–D1, D1–D2 | 가까운 그룹 내 적체 우선, 먼 그룹 내부의 오래된 요청 우선 |
| D0–W0, D1–W2 | 대기 예외 하나의 효과, 거리·적체 방식에 전역 대기 예외를 더한 효과 |
| D1–Q0 | 가까운 쪽에서만 적체 우선 vs 전역 적체 우선 |
| D0–U0, U0–U1 | 긴급 우선, 긴급 그룹에서 대기 예외의 효과 |
| D0–L0, L1–L2 | 적재 거리 우선, 장거리 그룹의 적체 예외 |

짝은 **같은 대수·시드에서** 비교한다. 둘 다 대기 규칙이 있으면 같은 경계값끼리 먼저 본다. 여러 대수에서 가장 좋은 값만 골라 한 규칙의 효과로 보고하지 않는다.

## 7. `qo` 부하 분석

`qo` 임계값은 임의 격자 대신 **입력 부하에서 출발한다.** 출발지별 평균 요청률 $\lambda_o=0.6\sum_j F_{oj}$:

| 출발지 | 기본 물동량/시간 | 평균 요청/시간 |
| --- | ---: | ---: |
| RECV | 63 | 37.8 |
| SORT (전부 긴급) | 59 | 35.4 |
| PICK | 54 | 32.4 |
| PACK | 53 | 31.8 |
| STOR-B | 51 | 30.6 |
| SHIP | 4 | 2.4 |
| **합계** | **284** | **170.4** |

이는 도착률이지 큐 분포가 아니다. 실제 큐는 $q_o(t)=A_o(t)-D_o(t)$(누적 발생 − 누적 배정)라, 발생률이 높아도 차를 쉽게 배정하면 작게 유지된다. 그래서 경계값은 실험으로 정한다(9.4절).

## 8. 거시 실험

### 8.1 대수 조사

첫 조사 대수는 19개다.

$$
\mathcal N_0=\{1,3,5,7,9,11,13,15\}\cup\{16,\dots,22\}\cup\{23,25,27,29\}
$$

16~22대는 기존 후보 18~20대 주변의 비교 구간이다. 같은 트리·시드 수 기준으로 30대 전수 조사보다 실행이 약 36.7% 적다. 대표 트리는 D0(거리)·W0(장기 대기)·U0(긴급)이다. 기존 18·19·20대 후보는 비교 기준일 뿐 탐색 범위를 18~20대로 제한하지 않는다.

인접 대수 추가 규칙:

- 조사한 대수 사이에서 반려 여부가 바뀌는 구간
- 같은 트리의 무반려 최저 비용과 10점 이내인 구간
- 29대가 유망하거나 상한을 점검할 때 30대

첫 조사는 이후 대수의 우선순위를 정할 뿐 다른 계열의 유망 대수를 영구 배제하지 않는다.

### 8.2 시드 단계

| 단계 | 시드 | 목적 |
| --- | --- | --- |
| 예비 비교 | 1001~1005 | 같은 대수에서 작은 구조 변경의 초기 효과 |
| 대수 조사 | 1001~1008 | 대표 트리별 차량 수 비교 |

### 8.3 예산과 3주 운영

- **예산:** 팀원당·대수당 서로 다른 완성 후보 최대 360개. 90·180·270·360개 시점의 최고값을 기록한다. 상한이자 점검점이지 채워야 할 목표가 아니다. 추가 실행은 별도 탐색으로 표시한다.
- **시드 확대:** 새 층 후보는 5시드로 먼저 보고 유망 후보만 16시드로 넓힌다. 연속 절반 축소(Successive Halving)와 Hyperband의 예산 배분을 참고하되 정확히 절반씩 탈락시킬 필요는 없다.

| 시기 | 주요 작업 |
| --- | --- |
| 1주차 | 대표 트리 대수 조사, 1~2층 시작 가설, 입력 부하 분석 |
| 2주차 | 3층 이상 선택적 확장, 변수·방향·임계값 최적화, 불필요한 노드 제거 |
| 3주차 | 팀 후보 취합, 별도 시드 검증, 공식 웹 평가와 발표 준비 |

### 8.4 분담

다섯 사람이 루트 하나씩 맡는다. 루트 대신 “멀리 있는 오래된 요청 구제”처럼 가지 위치나 변수 조합에 관한 가설을 맡아도 된다. 다른 루트나 교차 계열도 탐색할 수 있으며, 출발 가설과 최종 루트를 모두 기록한다. 서로 다른 출발점에서 같은 대수·같은 정규화 트리에 도달하면 비용은 한 번만 계산해 재사용하고, 출발 경로와 사용 예산은 각자 기록한다.

## 9. 미시 실험 — 선택적 층별 확장

### 9.1 확장 연산

현재 트리 $\mathcal T_k$의 빈 자식 위치 $\ell$에 규칙 $v=(f,d,\theta)$를 하나 붙인다.

$$
\mathcal T'=\operatorname{Expand}(\mathcal T_k,\ell,f,d,\theta),\qquad
\mathcal N(\mathcal T_k)=\{\mathcal T' \mid \text{필수 제약과 논리 축소 통과}\}
$$

$f\in\{de,dl,w,qo,urg\}$, $d\in\{\min,\max\}$, $\theta$는 3절의 후보값이다. 현재 허용한 층보다 깊은 노드는 만들지 않고, 노드가 9개면 확장을 멈춘다. 한 층에 여러 위치를 동시에 채우지 않는다. 위치별 확장안을 독립적으로 비교한 뒤 조합 효과를 따로 확인한다. 노드가 서로 영향을 줄 때는 각각 바꾼 후보와 둘을 함께 바꾼 후보를 같은 입력에서 비교한다.

### 9.2 효과 측정 — 공통 난수 짝 비교

부모 $\mathcal T$와 확장 $\mathcal T'$는 **같은 대수·같은 시드**에서 비교한다(Common Random Numbers, 공통 난수). 후보끼리 다른 요청을 받아 생기는 비교 잡음을 줄인다.

$$
\Delta_s=C_s(n,\mathcal T)-C_s(n,\mathcal T'),\qquad
\overline\Delta=\frac{1}{|S|}\sum_{s\in S}\Delta_s,\qquad
SE(\overline\Delta)=\frac{\operatorname{SD}(\Delta_s)}{\sqrt{|S|}}
$$

$\overline\Delta>0$이면 확장이 비용을 낮춘 것이다. $|\overline\Delta|$가 $SE$와 비슷하거나 반려가 엇갈리면 순위를 유보하고 시드를 늘린다. 5시드에서 조금 양수인 것만으로 우수함을 주장하지 않는다.

### 9.3 다음 층과 종료

| 질문 | 근거 | 다음 행동 |
| --- | --- | --- |
| 노드가 실제로 쓰이는가? | 도달률 | 도달 없으면 우선순위 낮춤 |
| 후보를 나누는가? | 유효 분기율 | 없으면 임계값 변경·제거 검토 |
| 선택을 바꾸는가? | 선택 변경률 | 없으면 추가 확장 가치 재검토 |
| 비용이 개선되는가? | 공통 시드 $\Delta_s$ | 유망 후보로 유지 |
| 특정 가지에 문제가 남는가? | 평균 대기·긴급 p95·큐 로그 | 그 가지를 확장 |
| 예산이 남았는가? | 노드 수·깊이·평가 횟수 | 다음 층 탐색 |

- **층마다 최고 후보 하나만 남기지 않는다.** `qo` 확장이 5시드 최고여도 구조가 다른 `urg` 확장이 긴급 대기를 더 안정적으로 줄이면 둘 다 보존한다. 같은 계열에서 비슷한 구조만 남지 않게 구조 다양성을 유지한다.
- **필수 종료:** 노드 9개 또는 깊이 5.
- **권장 종료:** 의미 있는 분기가 거의 없거나, 여러 확장안이 비용을 안정적으로 낮추지 못할 때. 한 층에서 개선이 없다고 탐색 전체를 끝내지는 않는다. 다른 시작 구조나 두 노드 동시 변경을 검토한다.
- 공식 목적함수에는 복잡도 벌점이 없다. 다만 **성능이 같으면 단순한 트리**를 고른다.

### 9.4 임계값 탐색

- **이산 변수(`de`, `dl`, `urg`):** 분기를 만드는 경계 전부를 시험한다.
- **`w`:** 0.5·1·2·4·8·16·32분의 로그 간격으로 넓게 훑고 유망 구간을 세분한다.
- **`qo`:** 7절의 부하에서 출발해 실제 큐로 정한다.
  1. 정책 무관 요청 분석: `--export-arrivals --seeds 1001,1002,1003,1004,1005,1006,1007,1008`로 시간대별 출발지 요청 수, 긴급 비율, 도착 간격을 본다(`--seeds`는 범위 표기를 지원하지 않음).
  2. 기준 정책의 실제 큐: D0와 U0를 실행해 매 배차 판단의 `seed, time, origin, qo, w, urg, de, dl, request_id, vehicle_id`와 시점별 전체·출발지별 큐 길이를 기록한다.
  3. 관측 분포로 경계 선정: 빈도가 높은 정수 경계와 분포가 바뀌는 구간부터 시험한다. 초기 격자가 필요하면 1·2·4·8을 쓰되 관측값에 맞춰 넓히거나 줄인다(대부분 `qo≤3`이면 1·2·3이 중요).
  4. Q 정책 재분석: Q 계열은 큐 분포 자체를 바꾸므로 Q 후보에서 형성된 큐를 다시 조사해 구간을 좁힌다.

## 10. 실험 축소와 진단 지표

논리 축소를 통과해도 쓸모 있는 노드라는 보장은 없다. **도달성 → 유효 분기 → 선택 영향 → 비용** 순서로 판단한다. 모든 판단에 쓰이는 `qo` 노드라도 대부분 `qo=1`이면 분기 효과가 거의 없고, 선택이 바뀌었다고 비용이 좋아진 것도 아니다.

배차 판단 $t$에서 엔진이 실제로 비교하는 압축 후보 집합을 $B_t$(3절), 노드 $v$까지 내려온 후보를 $B_t(v)$, 판단 횟수를 $M$이라 한다.

| 진단 | 지표 | 읽는 법 |
| --- | --- | --- |
| Reachability(도달성) | $R_v=\dfrac{\sum_t\lvert B_t(v)\rvert}{\sum_t\lvert B_t\rvert}$ | 낮으면 영향 줄 기회가 적다 |
| Effective Split(유효 분기) | $S_v=\dfrac{\sum_t \mathbf 1[\exists a,b\in B_t(v): f_v(a)\le\theta_v<f_v(b)]}{\sum_t\mathbf 1[\lvert B_t(v)\rvert\ge 2]}$ | 분모 0이면 0%가 아니라 **측정 불가** |
| Decision Impact(선택 영향) | $F_v=\dfrac1M\sum_t\mathbf 1[a_t^{\mathcal T}\ne a_t^{\mathcal T\setminus v}]$ | 같은 상태에서 $v$를 뺀 정책이 다른 조합을 고르는 비율 |
| 동점률 | $T_{\mathcal T}=\dfrac1M\sum_t\mathbf 1[\lvert\arg\min_{a\in B_t}P_{\mathcal T}(a)\rvert\ge 2]$ | 최상위 우선순위에 후보가 여럿 남아 기본 `de` 규칙으로 정해진 비율 |
| Cost Impact(비용 영향) | 9.2절의 $\overline\Delta$ | 다른 선택이 실제로 총비용을 낮추는가 |

- $F_v$는 **같은 상태를 입력받는 반사실 평가**다. 노드를 뺀 정책을 처음부터 다시 시뮬레이션한 결과와 구별한다.
- $\mathcal T\setminus v$는 **$v$ 자리를 비교 종료(0)로 바꾼 트리**다(하위 트리 함께 제거). `w(min)` 노드를 빼면 압축 후보도 달라지므로 반사실 정책의 후보 집합은 다시 만든다.
- 동점률이 높다고 나쁜 것은 아니다. 최근접 선택이 충분히 좋으면 동점을 두는 편이 낫다.

| 관측 | 해석 | 후속 행동 |
| --- | --- | --- |
| 도달률 낮음 | 분기 조건이 드묾 | 다른 가지 확장 우선 |
| 분기율 낮음 | 임계값이 후보를 못 나눔 | 임계값 재설정 또는 제거 |
| 선택 변경률 낮음 | 실제 선택에 영향 적음 | 제거 후보 |
| 변경률 높고 비용 악화 | 잘못된 결정 유도 | 변수·방향·위치 변경 |
| 평균 대기만 악화 | 전체 효율 저하 | `de`·`dl`·`qo` 조합 검토 |
| 긴급 p95만 악화 | 긴급 보호 부족 | `urg`·`w`·`de` 관계 검토 |
| 특정 출발지 큐 증가 | 편중·장기 소외 | `qo`와 `w`를 함께 분석 |

관측된 변경률이 0%여도 모든 시드에서 영향이 없다고 단정하지 않는다. 논리적으로 동등성이 증명된 노드만 완전히 제거하고, 나머지는 관측 범위를 적는다.

**공통 구현 과제** (한 번 구현해 다섯 명이 사용, 공식 배차·비용 계산을 바꾸지 않는 별도 모드)

- 배차 판단 시점의 압축 후보별 변수값과 실제 선택 기록
- 노드별 도달률·유효 분기율·선택 변경률·동점률 계산
- 출발지별 `qo`·`w` 분포 분석
- 부모·자식 트리의 시드별 비용 차이 자동 비교
- 정적 유효성·중복 검사와 정규화된 트리 생성

## 11. 검증 절차와 기록

1. **개인 후보 선정:** 팀원별 새 후보 최대 2개 + 기존 기준 후보 3개(중복 제거 전 최대 13개).
2. **새 32시드 비교(2001~2032):** 반려와 시드별 비용 차이로 선별한다. 검증 성능을 보고 무제한 재탐색하지 않는다.
3. **최종 후보 고정:** 새 후보 최대 3개 + 기존 기준 1개.
4. **최종 64시드(3001~3064):** 일반화 성능 확인. 이 결과로 후보를 고치면 새 검증 시드가 필요하다.
5. **공식 웹 평가:** 최종 새 후보 최대 2개 + 기존 기준 1개를 같은 CSV로 평가한다. 로컬과 다르면 원인을 기록한다.

반려된 후보는 성공한 시드의 평균만으로 순위를 올리지 않는다. 대표 실행에는 요청 발생·배정·픽업·하차 시각과 출발지별 대기열을 기록한다.

| 기록 항목 | 필수 |
| --- | --- |
| 후보 ID, 루트 계열, 부모 후보 ID | 필수 |
| 전체 트리와 대수 | 필수 |
| 엔진 커밋, 케이스 버전 | 필수 |
| 시드 집합, 평가 횟수, 집계 방식 | 필수 |
| 반려 여부, 시드별 비용 | 필수 |
| 평균 대기, 긴급 p95, 최대·종료 큐 | 필수 |
| 정적 유효성·중복 검사 | 필수 |
| 노드별 진단 지표 | 진단 실행 시 |
| 다음 확장 판단과 이유 | 필수 |
| 공식 웹 점수 | 공식 평가 후 |

같은 엔진·케이스·시드에서 이미 평가한 정책은 결과를 재사용한다.

## 12. 사람과 에이전트의 역할

**에이전트는 필수 제약을 자동 처리하고, 사람은 무엇을 검증할지와 다음 방향을 정한다.** 사람이 모든 임계값을 고를 필요는 없다. 어떤 질문을 실험할지를 정하고 그 안의 수치 비교는 에이전트에 맡긴다.

| 작업 | 담당 |
| --- | --- |
| 공식 제약 준수 검사, 무효·중복 노드 제거 | 에이전트 |
| 루트의 초기 가설 | 담당 팀원 (에이전트 제안) |
| 어느 가지를 확장할지 | 담당 팀원 최종 판단 |
| 변수·방향·임계값 후보 생성, 허용 범위 내 시뮬레이션, 결과 분석·추천 | 에이전트 |
| 추가 실험 방향, 최종 대수·트리 선정 | 담당 팀원 |
| 팀 후보 취합·공식 평가 | 팀 공동 |

**파일 구조.** 기존 개인 폴더를 쓴다.

~~~text
docs/notes/experiment-design.md   이 문서 (거시+미시 통합)
solutions/<개인 폴더>/
  root-plan.md      개인 가설·탐색 계획 (부록 A 템플릿)
  <후보ID>.csv      대수와 완성 트리 전체를 담은 공식 제출 파일
  <후보ID>.md       출발 가설, 이전 후보에서 바꾼 점, 실행 조건과 결과 위치
~~~

모든 팀원 에이전트는 [README](../../README.md), 이 문서, 개인 `root-plan.md`를 읽고 시작한다. 에이전트는 매 실험 후 **설계 가설 · 정적 검증 · 실험 결과 · 다음 제안**을 구분해 반환한다. 로컬 시드 결과와 공식 웹 점수를 섞지 않고, 공식 점수가 없으면 “미평가”로 적는다.

**중복 방지.** 착수 전 GitHub 이슈와 [탐색 현황판](../experiment/index.html#coverage)을 확인한다. 이슈 제목에 보드의 EXP 식별자를 넣고 담당·브랜치·예정 규칙·임계값·시드·엔진 커밋을 남긴다. 현황판은 참고 골격 15개 × 기본 대수 19개를 펼친 계획 단위이며, 한 사람의 평가 예산 360회와 단위가 다르다.
