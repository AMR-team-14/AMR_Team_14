공개 파일에서 확인한 사례

곽민재의 19대 최종안과 19대 후보는 동일합니다. 19대와 20대 후보는 같은 트리 골격을 쓰고, 대수와 가까운 거리 쪽 대기 규칙 등이 다릅니다.

보고서는 GitHub Actions 실행 요약에 남습니다. 별도 검증은 공통 32시드로 후보를 선별하고, 고정한 후보를 새 64시드에서 평가합니다.

①은 고정 운송 경로, ②는 같은 출발지, ●는 거리·대기·적체 사이의 상호작용입니다. ○는 이번에 강조하지 않은 쌍입니다. 흐린 칸은 자기 자신이거나 이미 표시한 쌍입니다.

관계특성 · 배차 순간의 예시담당자가 적용할 부분
① urg × dl이 케이스의 긴급은 모두 SORT에서 싣고 SHIP에서 내립니다. 모두 25m이고, 일반 요청 중에도 25m가 있습니다.urg dl
긴급 루트 담당은 긴급 가지 아래에서 de나 w를 비교합니다. 적재 거리 담당은 25m 그룹 안에 urg를 넣어 긴급을 따로 우선할 수 있습니다.
② urg × qo10시에 SORT에 미배정 6건이 있고 둘이 긴급이면 두 긴급 요청 모두 qo=6입니다. 11시에 SORT에 1건만 남으면 그 요청은 qo=1입니다.urg qo
긴급 가지에서 qo는 같은 순간의 두 긴급 요청을 가르지 못합니다. 대신 qo>3이면 가까운 차, qo≤3이면 오래 기다린 요청을 먼저 보도록 자식 규칙을 바꿔 시험하세요.

3주 탐색 현황

가로는 대수, 세로는 루트와 하위 가지를 정한 시작 구조입니다. 기본 15구조 × 19대수 = 285칸입니다. 칸 안에서는 방향·임계값·시드별로 실험이 더 나뉩니다.

칸을 누르면 구조·대수·후보·시드와 팀원의 진행 기록을 확인할 수 있습니다.

1주차에는 거리 우선(de), 장기 대기 우선(w), 긴급 우선(urg) 대표 트리 3개로 대수부터 훑고, 살아남은 대수에서 나머지 시작 구조를 비교합니다. 2주차에는 유망 구조의 방향과 경계값을 좁히고, 3주차에는 후보를 고정해 새 시드와 공식 점수로 검증합니다.

착수 전 해당 칸의 GitHub 이슈에서 진행 중인 범위를 확인하세요. 팀원이나 에이전트는 같은 칸에 담당자·브랜치·완성 CSV 또는 변경할 규칙·시드 범위·엔진 커밋을 적고, 끝나면 후보 커밋과 시드별 결과를 연결합니다. 비어 있는 칸은 현재 읽은 자료에 제출 기록이 없다는 뜻입니다.
