겹치미 · 매일 후보 취합

GitHub Actions가 공동 브랜치의 개인 폴더를 읽고, 누가 만든 어떤 후보의 어느 부분이 겹치는지 표시합니다.

같은 대수 · 같은 트리

경계값·방향·lo와 hi 가지까지 같으면 한 번만 평가합니다. 모든 파일과 제출자 이름을 남깁니다.

같은 골격 · 다른 값

노드 위치와 변수가 같을 때 서로 다른 대수·방향·경계값을 표시합니다. 같은 시드에서 각각 평가합니다.

비슷한 루트와 주요 가지

루트와 바로 아래의 두 가지가 비슷하면 어느 경로가 달라졌는지 표시합니다. 두 담당자가 비교할 후보입니다.

공개 파일에서 확인한 사례

곽민재의 19대 최종안과 19대 후보는 동일합니다. 19대와 20대 후보는 같은 트리 골격을 쓰고, 대수와 가까운 거리 쪽 대기 규칙 등이 다릅니다.

보고서는 GitHub Actions 실행 요약에 남습니다. 별도 검증은 공통 32시드로 후보를 선별하고, 고정한 후보를 새 64시드에서 평가합니다.

작은 대수는 유지, 큰 대수는 선별

낮은 대수의 반려도 기록합니다. 상단은 다섯 대표 트리로 먼저 확인하고, 경쟁력이 나온 구간에만 전체 후보를 추가합니다.

39개 버전 평가5개 대표만 확인초기 보류조건 충족 시 39개 평가

확장 조건 상단 대수의 대표가 8시드를 모두 통과하고, 같은 대표의 1~22대 최저 비용보다 10점 이내로 뒤지면 그 대수와 인접 대수에서 전체 버전을 평가합니다. 기본 구간에서 같은 대표가 전부 반려인데 상단에서 통과해도 확장합니다. 기본 구간 전체 선두가 22대면 23·24대를 추가합니다. 위 격자의 노란 칸은 조건 충족을 가정한 미리보기입니다.
