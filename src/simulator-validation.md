# 시뮬레이터 검증과 사용 범위

로컬 엔진은 같은 요청 목록에서 대수와 배차 트리를 비교하고 후보를 줄이는 데 쓸 수 있습니다. 최종 제출 후보는 공식 웹에서 같은 파일로 다시 평가합니다. 공식과 로컬의 종합 점수가 가깝더라도 후보 간 격차가 더 작으면 순위가 바뀔 수 있습니다.

## 어떤 입력을 비교하는가

- 시드 11은 공식 배차 로그에서 복원한 요청 8,453건입니다. 복원 파일의 시각 해상도는 0.001분입니다. 현재 엔진은 이 요청 목록으로 배차와 주행을 다시 계산합니다.
- 시드 12~15와 그 밖의 생성 시드는 로컬 Mulberry32 난수 생성기와 케이스의 도착률·운송 흐름을 사용합니다. 숫자가 같은 시드라도 생성기, 난수 사용 순서 또는 시각 처리 방식이 다르면 요청 목록이 달라질 수 있습니다. 공식 12~15번 요청을 확보하지 못했으므로 차이의 원인을 특정하지 않았습니다.
- 같은 로컬 시드와 케이스로 후보들을 비교하면 요청 발생 시각과 출발지·목적지가 같습니다. 다만 차량 배정, 교차로 대기, 픽업은 정책에 따라 달라져 후보마다 다시 시뮬레이션합니다. [저장된 요청 목록](../data/scenarios/)

## 현재 엔진으로 다시 계산한 결과

기존 세 후보를 Windows에서 C++ 명령줄 엔진으로 재평가했습니다. 공식 웹 열은 [팀 보고서](../solutions/KMJ/final_agv_report.md)에 기록된 값이며 이번 비교에서 웹을 다시 실행하지는 않았습니다.

| 설계 | 로컬 시드 11~15 | 로컬 시드 101~150 | 추가 로컬 시드 151~200 | 공식 웹 기록 | 웹 − 로컬 11~15 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 18대 후보 | 1,199.76 | 1,196.68 | **1,199.73** | 1,205.54 | +5.78 |
| 19대 후보 | **1,198.18** | 1,198.62 | 1,203.61 | **1,201.39** | +3.21 |
| 20대 후보 | 1,199.71 | 1,207.43 | 1,207.59 | 1,207.63 | +7.92 |

151~200은 기존 `--robust` 탐색 코드가 쓰는 11~15 및 101~150과 겹치지 않습니다. 세 후보 모두 추가 50시드에서 반려 0건이었습니다. 같은 시드끼리 비교한 19대 후보 − 18대 후보의 평균 차이는 **+3.88점**이고, 95% 대응 t 신뢰구간은 **+0.25~+7.52점**입니다. 이 구간은 로컬 생성 모델에서 두 고정 후보를 비교한 결과입니다. 공식 웹 기록에서는 반대로 19대 후보가 4.15점 앞섰습니다. 다수 시드는 로컬 모델 안의 표본 변동을 줄여 주고, 공식 모델이나 요청 목록과의 차이는 남습니다.

당시 101~150 시드는 후보를 고르는 데도 쓰였으므로 보고서의 `unseen50` 수치는 독립 검증으로 해석할 수 없습니다. 새로운 후보를 고를 때는 같은 시드 집합으로 탐색한 뒤, 선택에 쓰지 않은 시드에서 비용 차이와 반려 건수를 함께 확인합니다.

## 보고서의 민감도 분석을 어디까지 쓸 수 있는가

| 분석 | 코드가 바꾼 것 | 해석 |
| --- | --- | --- |
| 차량 대수 | 한 트리를 고정하고 대수만 16~23대로 변경 | 해당 트리에서 차량을 늘리거나 줄인 효과입니다. 대수마다 트리를 다시 최적화한 비교와 다릅니다. |
| 노드 제거 | 루트를 제외한 각 노드에 들어오는 가지를 종료 처리 | 해당 노드에 자식이 있으면 **그 아래 하위 트리 전체**가 빠집니다. 점수 차이가 그 노드 하나의 공헌도라는 뜻은 아닙니다. |
| 임계값 | 다른 규칙을 고정하고 노드 하나의 임계값만 변경 | 시험한 값 안의 조건부 반응입니다. 두 경계의 상호작용이나 전체 최적성은 이 분석으로 판정할 수 없습니다. |

보고서 4.1과 4.2는 최종 파일을 가리키지만, 적힌 수치는 **18대 후보의 트리**로 재현됩니다. 예를 들어 그 트리를 18대에 적용한 로컬 5시드 평균은 **1,199.76**, 19대로만 바꾸면 **1,211.59**입니다. 최종 19대 파일 자체의 로컬 평균은 **1,198.18**입니다. 보고서 4.3의 #3 가지 제거 **+36.73점**, #5 가지 제거 **+33.63점**도 18대 후보의 101~150 결과와 맞았습니다. 최종 19대 트리의 #5는 `urg`로 규칙 자체가 다릅니다. 표에 나온 효과를 최종 19대 트리로 옮겨 읽으면 안 됩니다. 구현은 [대수·노드·임계값 분석 코드](search.cpp#L157)를 참고하세요.

이 방법은 특정 트리에서 어느 부분이 민감한지 살피는 데 유용합니다. 보고서의 “전역 최소”나 “절대 최적”은 시험 범위 밖까지 뒷받침하지 못합니다. 또 일부 표의 로컬 평균은 반려된 시드를 빼고 계산하므로, 평균과 반려율을 함께 읽어야 합니다.

## 재현과 남은 확인

```sh
node tools/build.mjs native
build/agv_opt --analyze solutions/KMJ/robust_best_18.csv
build/agv_opt --analyze solutions/KMJ/robust_best_19.csv
build/agv_opt --eval-json solutions/KMJ/robust_best_19.csv --seeds 11,12,13,14,15
```

Windows에서는 실행 파일이 `build/agv_opt.exe`입니다. 추가 시드를 재현하려면 `--seeds`에 151~200을 쉼표로 이어 전달합니다. 저장소의 [엔진 검사](../tests/engine.mjs)는 로컬 명령줄 결과와 WebAssembly(브라우저에서 실행하는 빌드)의 결과를 대조합니다. 이번 변경에서 이 검사를 실행했고, 기존 후보 파일 4개의 시드별 점수와 명령줄·WebAssembly 결과 일치 검사를 통과했습니다. 위의 민감도 분석과 추가 50시드 평가는 명령줄 엔진에서 수행했습니다.

공식과 로컬의 동작이 같은지 더 확인하려면 시드 11에서 **같은 트리·대수·요청 목록**으로 배정 차량과 픽업 시각을 사건 순서대로 대조해야 합니다. 이번에는 공식 이벤트 단위 대조를 수행하지 않았습니다.
