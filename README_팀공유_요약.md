# AGV 운영 규칙 설계 최적화 · 팀 공유 패키지 안내

## 1. 왜 Python에서 C++20으로 전환했는가?
1. **Python GIL 및 인터프리터 루프 한계:**
   - Python의 일반 `threading`은 GIL(Global Interpreter Lock) 때문에 멀티코어 CPU 병렬화가 불가능합니다.
   - `multiprocessing`으로 GIL을 우회할 수는 있으나, 이산 사건 시뮬레이션(`while ev_pq:`) 자체가 수만 번의 우선순위 큐/객체 연산을 반복하는 CPU-bound 루프라 파이썬 바이트코드 인터프리터 오버헤드가 큽니다(5시드 평가 약 `0.5~0.7초`).
2. **C++20 + `std::thread` 10코어 병렬화의 압도적 성능:**
   - `g++ -O3 -std=c++20` 네이티브 컴파일과 `std::thread` 10코어 공유 메모리 병렬화를 적용해 시뮬레이션 속도를 대폭 끌어올렸습니다.
   - 이를 통해 **단순 5시드 과적합을 피하고 55개 시드(실제 시드 11 + 독립 시드 54개)를 동시에 평가·최적화**하는 파이프라인을 실용 시간 내에 가동할 수 있게 되었습니다.

## 2. 현재 C++ 최적화 파이프라인 (`agv_opt.cpp`)
* **완전 독립형 단일 엔진:** 외부 파이썬 의존성 없이 `agv_case_data (1).json`과 `agv_dispatch_log_seed11 (1).csv`를 직접 파싱하며, `Mulberry32` 난수 생성기·Dijkstra 최단경로·동일시각 일괄처리(`abs(dt) < 1e-9`)·교차로 FIFO를 파이썬 참조 모델과 소수점 4자리(`0.0000` 오차)까지 동일하게 구현했습니다.
* **핵심 고속화 기법:**
  1. **비교차로 경로 압축(`COMP_PATH`):** 중간 직선 노드 이벤트를 합쳐 힙 연산 최소화
  2. **플로우 헤드 & 위치 대표 지배성:** 동일 출발지·목적지 플로우와 동일 노드 대기 AGV 중 지배 불가능한 쌍 제거
  3. **`w min` 이분탐색 지배성:** `w min` 노드가 있어도 큐 전체를 스캔하지 않고 임계값 경계 요청만 $O(\log Q)$ 탐색
  4. **2단계 55시드 스크리닝:** 12개 시드 + 조기 혼잡 컷오프(`qcap=65`)로 불량 트리를 먼저 걸러낸 뒤, 상위 후보만 55개 시드 전체로 정밀 최적화
* **지원 CLI 모드:**
  - `agv_opt.exe --eval <csv>`: 공개 5시드 정밀 채점
  - `agv_opt.exe --analyze <csv>`: 대수 민감도(`n=16~23`), 노드 Ablation, 경계값 민감도, 미공개 50시드 분석
  - `agv_opt.exe --robust`: `n=18, 19, 20` 55시드 범용 최적화 실행
