# Case 1 논리 과정 정리 (박진홍, 11/23 기준)

- **무엇:** 리더보드 1,170.20(1위). 2위 1,178.00, 팀 기존 최고 1,185.42.
- **왜 가능했나:** 나무의 맨 위 기준이 「주문이 들어온 순간」과 「차가 빈 순간」을 가르는 스위치라는 것을 찾았고, 웹과 똑같이 계산하는 엔진으로 공개 시드 점수를 제출 없이 수십만 번 확인했다.
- **결과:** 구조 개선으로 약 12점(팀 최고안 대비, 새 시드 기준), 공개 시드에 맞춘 선택으로 약 10점을 더 내렸다. 형식 안에서 구조로 더 줄일 여지는 찾지 못했다.

자세한 실험 기록은 [EXPERIMENTS.md](EXPERIMENTS.md)(실험 1~27), 다음 계획은 [PLAN_cases.md](PLAN_cases.md)에 있다.

## 1. 문제를 어떻게 봤나
총비용 = 15 × 대수 + 102.24 × 평균 대기(분) + 100 × 긴급 대기 95분위(분). 대기는 「주문 발생 → 차가 출발지에 도착」이다.

배차는 두 상황뿐이다(실험 10 진단).

| 상황 | 나무가 고르는 것 | 21대에서 비중 |
|---|---|---|
| 도착 즉시: 주문이 들어온 순간 빈 차가 있다 | 어느 차를 보낼까 | 약 69% |
| 대기 후: 빈 차가 없어 쌓였다가 차가 비었다 | 어느 주문을 잡을까 | 약 31% |

이 구분은 AGV 배차 문헌의 고전 분류(작업장 기점 / 차량 기점 규칙, Egbelu & Tanchoco 1984, 재인용)와 같다.

## 2. 점수가 내려간 순서

| 단계 | 한 일 | 리더보드 | 새 시드 평균 |
|---|---|---|---|
| 팀 최고안(민재) | de 루트 9노드, 19대 | 1,185.42 | 약 1,192 |
| 승민 w 루트안 | 루트 `w max 0.05`, 21대 | 1,201.02 | 약 1,188 |
| ① 루트 경계값 0.05 → 0.001 | 「방금 들어온 주문」만 정확히 가름 | 1,187.52 | 약 1,182 |
| ② 쓸모없는 노드 2개 제거 + 대기 가지에 `dl min 65` | 먼 차는 짧은 운반부터 | 1,189.84 | 약 1,181 |
| ③ 기대값이 같은 후보 중 공개 점수 낮은 것 | 9번째 기준 1개 + 루트 경계값 | 1,177.97 | 약 1,181 |
| ④ 공개 점수 직접 최적화 | 대수 20, 루트 경계값 0.00174 | 1,171.67 | 약 1,182 |
| ⑤ 루트 경계값을 0.00001 간격으로 훑기 | 21대, 경계값 0.00341 | **1,170.20** | 약 1,184 |

- ① · ②는 구조 개선이다. 새 시드 1,000개 짝비교로 확인했다(승민안 대비 −7.2 ± 0.4, 민재안 대비 −11.7 ± 0.5).
- ③ ~ ⑤는 공개 시드 5개에 맞춘 선택이다. 새 시드 평균은 좋아지지 않는다. 모두 새 시드 1,000개에서 반려 0건을 확인하고 제출했다.

## 3. 지금 나무가 하는 일 (제출안)
```
w(max, 0.00341)                         ← 방금 들어온 주문인가?
├ 방금 들어온 주문(도착 즉시): dl(min, 50)
│   └ 운반 거리 50m 이하: de(max, 180)   ← 205m 떨어진 SHIP의 빈 차를 먼저 보낸다(쌓인 차 순환)
└ 기다린 주문(대기 후): de(min, 65)       ← 65m 이내 주문 먼저
    ├ 가까운 주문: qo(max, 1)             ← 주문이 2건 이상 쌓인 출발지 먼저
    │   └ 쌓인 곳: urg(max)               ← 그 안에서는 긴급 먼저
    │       └ 일반: dl(min, 65)
    └ 먼 주문: urg(min)                   ← 먼 긴급은 미룬다(곧 가까운 차가 생긴다)
        └ 일반: qo(max, 2)
```
강의 7의 규칙 이름으로는 STTF(de), 붐비는 출발지 먼저(qo), 긴급 먼저(urg), SPT(dl)를 상황별로 섞은 계층형 규칙이다.

## 4. 왜 더 못 줄이나
- **Gurobi 하한(실험 18):** 빈 차 이동을 이론상 최소(주문당 35.6m)로 하면 총비용 ≥ 275. 실제 빈 차 이동은 약 82m다.
- **형식의 한계(실험 20~22):** 형식 밖 규칙 하나(「RECV 주문이 들어오면 SHIP의 빈 차를 보낸다」)를 넣으면 같은 21대에서 1,181 → 1,097, 23대에서 1,064가 된다. 제출 형식의 특성 5개로는 RECV 주문을 다른 25m 주문과 구분할 수 없어 이 규칙을 쓸 수 없다.
- **형식 안 탐색:** 도착 가지 규칙 2,089개(21대)와 3,891개(22~24대) 전수, 대기 가지 이웃 약 3만 2천 개에서 개선이 없었다.
- **공개 점수:** 후보 약 23만 개 중 최저가 1,170.20이다. 계산을 10배 늘릴 때마다 1.5~2점쯤 내려간다. 11/23 밤 GitHub Actions(20조각 × 3파도)로 더 찾는 중이다.

## 5. 방법 (강의 65쪽의 시뮬레이션 기반 최적화와 대응)
| 강의의 항목 | 우리가 한 것 |
|---|---|
| 대수는 전부 훑는다 | 19~24대를 나무와 함께 비교 |
| 나무는 기준 하나씩 바꾸는 탐색 | 1~4곳 변이 + 단계 선별(2 → 6 → 16 → 48 → 120묶음) |
| 같은 시드로 비교한다 | 5시드 묶음 짝비교, 표준오차와 t 값 보고 |
| 공개 시드 과적합을 경계한다 | 학습 → 확인 → 최종 시드를 따로 두고, 공개 점수에 맞춘 단계는 그렇다고 적음 |

도구: 웹 채점 엔진을 연산 순서까지 옮긴 C++ 엔진(`cpp/agvx.cpp`)과 Node 엔진(`jsim.js`). 웹 원본과 대조해 차이가 출력 자릿수 수준임을 확인했고, 제출 전 계산값과 리더보드 값이 네 번 모두 같았다(1,180.42 / 1,177.97 / 1,171.67 / 1,170.20).

## 6. 시행착오에서 배운 것
- 후보 여럿 중 1등은 새 시드에서 자주 사라진다(실험 3 · 8). 고를 때 쓴 시드와 확인하는 시드를 나눈다.
- 직접 짠 난수 버그와 배열 크기 버그로 두 번 헛돌았다. 새 탐색 코드는 「서로 다른 후보 수」를 먼저 찍어 본다.
- 예상을 적고 결과와 대조했다. 공개 점수 예상(1,163~1,168)은 빗나갔다. 행동이 서로 다른 후보 수를 과대평가했기 때문이다.
- Case 1은 무작위 시드로 채점한다고 했으므로(11/23 수업), 리더보드 숫자와 채점 숫자가 다를 수 있다. 새 시드 평균이 가장 좋은 안은 `answer_jinhong_best.csv`로 따로 둔다.
