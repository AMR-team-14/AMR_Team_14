# 리더보드 더 낮추기 로드맵 (박진홍, 11/24 08:20 작성)

- **무엇:** 다섯 케이스의 리더보드 점수를 지금보다 더 낮추는 순서와 멈춤 기준이다.
- **왜 이 순서인가:** Case 2~5는 공개 시드 점수가 그대로 성적이고, 밤사이 Case 4 · 5를 내린 방법을 Case 2 · 3에는 아직 쓰지 않았다. Case 1은 4,379만 개를 봐도 그대로라 거의 바닥이다.
- **결과(목표):** Case 3 → Case 2 → Case 4 → Case 5 → Case 1 순서로 한 번에 하나씩 한다. 단계마다 예상 점수를 먼저 적고 결과와 대조한다.

「새 방법」은 밤샘 루프에서 통한 세 가지다(도구 `night.js`).
1. **규칙을 맞춘 뒤의 점수로 방향을 고른다.** 방향 후보마다 대수와 「흐름 묶음별로 얼마나 먼 차를 보낼지」를 다시 맞춘 값으로 순위를 매긴다(`dirpf`, `dirls2`). 단순 규칙 점수로 고르면 좋은 방향을 놓친다(Case 4 · 5에서 확인).
2. **재배치 규칙을 형식 안에서 전수로 찾는다.** 「이 묶음의 주문에는 일부러 먼 차를 보낸다」를 대수 · 묶음 · 반경 조합으로 전부 본다(`s4`, `famscan`).
3. **골짜기를 찾은 뒤에만 다듬는다.** 방향 고정 탐색 → 방향 · 나무 동시 탐색 → 루트 w 경계값 훑기 순서다.

## 1. 단계별 계획
각 단계는 「질문 → 예상 → 실험 → 결과와 예상의 차이 → 다음 질문」으로 돌리고 그 케이스 NOTES에 적는다.

### 1단계 — Case 3 (지금 시작)
- **왜 먼저:** 탐색량이 가장 적고(7만 6천 개), 2위와 19점이라 따라잡힐 수 있고, 비용의 53%가 긴급 95분위(522점)에 몰려 있다.
- **할 일**
  1. 리더보드 순위 확인.
  2. 강연결 방향 54개 전부에 「규칙을 맞춘 뒤 점수」를 다시 매긴다. 54개뿐이라 전수가 된다.
  3. 상위 방향에서 재배치 규칙 전수(대수 21~24), 긴급 주문을 dl로 둘로 가르는 구조(`urg → dl`) 훑기.
  4. 골짜기 다듬기 → 웹 대조 → 제출.
- **예상:** 965~972(지금보다 5~11점). 방향 후보가 54개뿐이라 Case 5 같은 큰 골짜기는 기대하지 않는다.
- **멈춤:** 세 회전 연속 개선이 없거나 2시간.

### 2단계 — Case 2
- **왜:** 공개 점수(617.16)가 새 시드 평균(613.17)보다 오히려 높다. 다른 케이스는 공개 점수가 평균보다 낮게 골라져 있으므로, 공개 시드에 맞춘 선택만으로도 여지가 있다. 답도 기준 3개뿐이라 남는 자리가 6개다.
- **할 일**
  1. GitHub Actions 실행 45272859577(20조각, 12:00쯤 끝남) 결과 모으기: `gh run download 45272859577 -D gha/dl2` → `node gha_case2_collect.js` → `pipe.js 2 eval` · `safety`.
  2. 방향을 「규칙을 맞춘 뒤 점수」로 다시 탐색(`dirls2`), 대수 24~28에서 방향 다시 풀기.
  3. 남는 기준 6개로 대기 가지 채우기 + 루트 w 경계값 훑기.
- **예상:** 605~612.
- **멈춤:** 세 회전 연속 개선이 없거나 2시간. 2위와 160점 넘게 벌어져 있어 길게 끌지 않는다.

- **할 일:** 순위 확인 → 밀렸거나 차이가 1점 안쪽이면 남은 아이디어 두 가지(통로를 더 뒤집어 재배치 묶음 넓히기, 19~20대 조합)를 돌린다. 801.44 안(0.03점)은 다른 개선과 묶어서만 낸다.
- **예상:** 799~801.
- **멈춤:** 1시간.

### 5단계 — Case 1 (진홍 결정 뒤)
- **상태:** 순수 나무로는 바닥(1,170.20, 실험 28).
- **남은 길:** 공유 나무(기준 하나를 두 갈래가 가리키는 CSV, 웹 검사 통과). 새 특성을 주는 것이 아니라서 예상 이득은 0~3점이다. 과제 설명이 「나무」라 형식 위반으로 보일 위험이 있다.
- **할 일:** 진홍이 「로컬로만 시험」을 정하면 점수 차이만 잰다. 제출 여부는 그 숫자를 보고 다시 정한다.

## 2. 공통 규칙
- **제출:** 우리 기록보다 낮고, 공개 시드에서 반려가 없고, 웹 「평가 실행」 값이 로컬 값과 같을 때 낸다. 회전 두세 번의 최저안을 모아서 내고, 단계당 5번 이내로 쓴다.
- **형식:** 순수 나무만 제출한다. 공유 나무 안은 `caseN/answer_caseN_shared.csv`로만 남긴다.
- **순위 확인:** 단계를 시작할 때와 끝낼 때 그 케이스 리더보드를 보고 NOTES에 적는다. 다른 팀도 내리고 있다.
- **한 번에 하나:** 로컬 실험은 한 번에 하나, 25분 이내로 자른다. 이 PC의 `sweepm.py`(WorldQuant)는 건드리지 않는다.
- **기록:** 회전마다 NOTES에 적고 커밋 · 푸시한다. 단계가 끝나면 이 파일의 아래 표를 채운다.
