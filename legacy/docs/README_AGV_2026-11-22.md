# AGV 배차 실험 작업 요약

2026-11-22 · AMR Team 14

교수님 웹의 Seed 11에서 거리 기준 정책(A)과 팀 최종 정책(B)을 비교했다. 차량 수는 19대로 같았다. **B의 로그 기반 총비용은 시간당 63.86천 원 낮았고, 입고장(RECV) 비긴급 주문의 대기시간 P95는 1.95분 길었다.** 10분을 넘긴 주문은 1건에서 54건으로 늘었다. 최종 정책을 평가할 때 전체 비용과 부서별 긴 대기를 함께 보는 것이 이번 분석의 발표 주제다.

분석 조건, 계산 방법, 해석 범위는 [AGV 배차 실험 종합 결론](./AGV_EXPERIMENT_CONCLUSIONS_2026-11-22.md)에 정리했다. 이 문서는 팀의 기존 루트 README와 함께 둘 수 있는 작업 요약이다.

## 작업 내용과 결과

| 작업 | 환경과 범위 | 결과 |
|---|---|---|
| 실험 설계와 사전 점검 | 팀 C++ 엔진과 정책 구현 검토 | 차량 수·정책·시드를 분리하고, 같은 주문 시나리오로 조건을 비교하는 설계를 확정했다. FCFS·STTF·URG는 로컬 정책으로 정의했다. |
| RQ1 예비·최종 검증 | 로컬 C++ · Pilot 600회, 최종 4,000회 | DT-1185의 STTF 대비 절감 폭은 19대보다 18대에서 19.78천 원/시간 컸다. 95% 신뢰구간은 16.38~23.19천 원/시간이다. DT-1185는 17~21대 모두에서 평균비용이 가장 낮았다. |
| 공동 선택과 순차 선택 비교 | 로컬 C++ · 기존 200개 시드로 조합 선택, 신규 200개로 평가 | STTF를 기준으로 차량 수를 먼저 확정하면 20대가 선택됐고, 공동 선택의 18대보다 8.85천 원/시간(0.74%) 더 들었다. 19대에서 정책을 먼저 정한 절차는 공동 선택과 같은 조합을 골랐다. |
| 팀 `main` 검토 | README, 제출 CSV, 명세, 최종·방법론 보고서, 코드 | SORT 유량 균형, 긴급 지연 원인, 트리 최적화는 기존 팀 작업에 포함돼 있었다. 후속 웹 실험의 질문은 RECV 비긴급 주문의 긴 대기로 정했다. |
| 주문 흐름과 웹 구현 범위 점검 | 입력 JSON, 고정 통로, 제출 트리 명세 | 평균 물량의 이상적 처리 작업량을 약 8.21대분으로 계산했다. 주행 중인 차의 도착 예정 시간은 제출 트리의 입력이 아니어서, 웹 실험에는 기존 형식의 배차 규칙을 사용했다. |
| RECV A/B 비교 | 교수님 웹 · Seed 11 · 차량 19대, 통로 방향 동일 | A에서 B로 바꾸면 RECV 비긴급 대기 P95는 6.84분에서 8.78분으로 늘었다. 전체 긴급 주문 대기 P95는 5.83분에서 5.12분으로 줄었다. |
| 발표 자료 | Python 그래프와 한 장 슬라이드, 30초 대본 | 로컬 RQ1 그래프 3장과 웹 RECV A/B 그래프 1장을 작성했다. 발표용 한 장에는 웹 로그에서 확인한 비용과 부서별 대기 차이를 넣었다. |

발표의 핵심 근거는 **교수님 웹에서 생성된 A/B 배차 로그**다. 로컬 RQ1과 순차 선택 실험은 연구 질문이 어떻게 발전했는지 설명하는 보조 자료로 쓸 수 있다. 웹 채점 결과 화면은 수집되지 않아, 위 비용은 Seed 11 로그에서 채점식을 적용해 재계산한 값이다.

## GitHub에 함께 둘 파일

두 Markdown 파일을 같은 폴더에 두면 서로 연결된다. 웹 결과를 재현할 수 있게 하려면 A/B 제출 CSV, 새 웹 로그 2개, 로그 집계 스크립트와 그래프를 함께 보관한다. 로그를 저장소에서 공유할 수 있는지 확인한 후 업로드하고, 웹 점수 화면을 확보하면 정책명과 점수의 시드 범위를 붙여 해당 로그와 연결한다.

로컬 보조 실험까지 재현할 경우 위 원자료와 함께 **실험용 C++ 수정본 또는 패치**를 보관한다. 원본 `main`의 엔진과 구분할 수 있는 이름을 쓴다. 예비실험 시드 `3001–3030`은 팀의 이전 로컬 검증 기록 `1001–4600`과 번호가 겹친다. 최종 RQ1 및 순차 선택의 새 평가 시드는 이 범위와 분리돼 있다.
