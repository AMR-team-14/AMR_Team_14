# younbean AGV 배차 탐색과 검증

AGV 19대와 기존 9노드 트리를 현 제출안으로 유지한다. 새 트리 구조와 대기시간 조합을 탐색해 두 후보를 고정한 뒤, 후보마다 신규 3,600개 시나리오를 기준안과 짝비교했다. 두 후보 모두 실격은 없었고, 통계적으로 우위가 확인된 후보는 없었다.

## 1. 어떤 알고리즘과 방법을 사용했는가

- **대규모 이웃 탐색**은 AGV 18·19·20대에서 각각 실행했다. 기준 트리와 각 대수에서 상위로 남은 트리에 규칙 3~4개 동시 변경 또는 하위 트리 재생성을 적용했다. 하위 트리를 만들 때 조상 노드의 특성을 제외하고 최대 9노드 제약을 유지했다. 대수별 8회, 회당 유효 고유 트리 96개로 총 2,304개를 1차 평가했다.
- **대기시간 중심 탐색**은 18·19대에서 근거리와 원거리의 대기시간 임계값을 함께 바꿨다. 출발지 대기열 기준을 1건에서 2건으로 올리거나 같은 두 조건을 긴급 우선으로 재배열한 후보도 비교했다. 총 646개를 1차 평가했다.
- 탐색에는 시드 `4601–4612` 12개로 1차 선별하고, 통과 후보를 `4601–4648` 48개로 평가했다. 마지막 후보 선정에는 별도 `4801–5040` 240개 시드를 사용했다. 각 실험에서 후보 하나를 고정한 뒤 각각 `6001–9600`, `10001–13600`에서 검증했다. 실격 0건과 짝비교 `t < −2`를 우위 기준으로 삼았다.

| 실험 | 선별된 후보 | 선별 240시드 차이 | 신규 3,600시드 차이 ± 표준오차 | 단측 95% 상한 | 후보 실격 |
|---|---|---:|---:|---:|---:|
| 대규모 이웃 | 18대, 기존 트리 | −0.51 | −0.218 ± 0.217 | +0.140 | 0 / 3,600 |
| 대기시간 중심 | 19대, 2.45→2.35분 및 0.75→0.70분 | −1.23 | +0.594 ± 0.203 | +0.927 | 0 / 3,600 |

차이는 후보 비용에서 같은 시나리오의 기준안 비용을 뺀 값이다. 단위는 천원/시간이며 음수면 후보가 유리하다. 18대는 차량비를 15점 아꼈지만 전체 평균 대기가 0.163분 늘었다. 긴급 대기시간의 95백분위수는 0.019분 줄어 총비용 차이가 작았다. 두 번째 후보는 기존 로컬 800시드에서도 1,191.93점으로 기준안 1,191.27점보다 높았다.

## 2. 파이프라인 코드

[agv_opt.cpp](../../agv_opt.cpp)는 팀 시뮬레이터와 기존 명령을 제공한다. [agv_yb_search.hpp](../../agv_yb_search.hpp)는 두 탐색과 짝비교 검증을 구현한다. 두 후보의 통로 방향과 트리 제약을 확인했고, 각각 15개 시드에서 빠른 엔진과 모든 배차 쌍을 검사한 엔진의 비용 차이가 0이었다.

Visual Studio 개발자 PowerShell에서 저장소 루트를 작업 폴더로 두고 실행한다.

```powershell
cl /nologo /std:c++20 /O2 /EHsc /utf-8 agv_opt.cpp /Fe:agv_opt.exe
.\agv_opt.exe --verify answer_final_best.csv
.\agv_opt.exe --yb-search answer_final_best.csv yb_lns_reproduced.csv 8
.\agv_opt.exe --yb-deadlines answer_final_best.csv yb_deadlines_reproduced.csv
.\agv_opt.exe --yb-audit answer_final_best.csv experiments/younbean/lns_candidate.csv 6001
.\agv_opt.exe --yb-audit answer_final_best.csv experiments/younbean/deadlines_candidate.csv 10001
```

`--yb-search`와 `--yb-deadlines`에는 새 출력 파일명을 지정한다. 같은 후보의 평가를 반복할 때는 보관한 CSV를 사용한다. 새 후보를 선택한 뒤에는 후보 선정과 이전 검증에 쓰지 않은 시드 범위로 최종 비교한다.

## 3. 왜 현재 해를 국소최적이라고 보는가

민재의 방법 A는 18·19대의 유효 이웃 4,093개를 대상으로 노드 1~2개 교체, 일부 구조 이동, 대기시간 격자를 단계적으로 비교했다. 19대에서 가장 가까운 후보의 3,600시드 비용 차이의 단측 95% 신뢰하한은 −0.39점이었다. 정의한 이웃과 선별 절차에서 0.5점 이상의 개선을 뒷받침할 후보가 없었다는 근거다. 이번 확장 탐색도 두 신규 시드 구간에서 기준안을 유지한다는 결론을 냈다. 3노드 이상 변경의 일부를 표본 탐색했으므로 전역 최적 여부는 열려 있다. [방법 A 검증 보고서](../../method_a_local_optimality_report.md)

## 4. 왜 개선하기 어려운가

팀의 웹 로그 분석에서는 가장 오래 지연된 긴급 요청 80건 중 24건이 배차 순간에 대기 요청 한 건과 유휴 차량 한 대뿐이었다. 이 상황을 줄이려면 그 직전 배차에서 차량이 어디에 남는지부터 바뀌어야 한다. 새 실험에서도 18대로 줄인 고정비 이득 대부분을 평균 대기 증가가 상쇄했고, 240개 시드에서 좋았던 임계값 조합은 신규 3,600개에서 역전됐다.

후속 실험에서 배차 한 건을 `PACK → SORT`로 바꾸고, 하역 완료와 다음 긴급 픽업을 직접 추적했다. 허용 특성으로 만든 후보를 별도 3,600시드에서도 비교했다. [SORT 빈 차 공급 실험](sort_supply.md)

근거리에서 오래 밀린 일반 요청에만 예외를 주는 트리를 구성했다. 8노드 대조안과 기존 9노드 제출안을 따로 비교해 예외의 효과와 실제 교체 비용을 분리했다. [Q01 오래된 적체 예외 실험](Q01-aged-backlog/README.md)

근거리 긴급 규칙을 유지한 채 일반 요청 예외 자체를 가상으로 검증하고, 9노드 안에서는 원거리 규칙을 옮기는 비용과 일반 픽업 지연 개선을 따로 측정했다. [Q02 긴급 규칙 유지 실험](Q02-aged-backlog-keep-urgent/README.md)

같은 요청 수에서 도착 집중의 길이와 구역 수를 나누고, 4분 예외와 대기열 기준의 효과를 따로 확인했다. [Q03 주문 집중 형태별 실험](Q03-backlog-demand-profiles/README.md)
