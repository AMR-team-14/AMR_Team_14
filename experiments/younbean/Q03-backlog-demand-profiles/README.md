# Q03 주문 집중 형태별 오래된 적체 실험

**기존 19대 제출안을 유지한다.** 같은 분량의 주문이 짧게 몰리는 경우와 길게 몰리는 경우를 분리했다. 4분 넘게 기다린 일반 요청을 우선하면 영향을 받은 구역의 긴 지연은 줄었지만, 시험한 네 가지 수요 조건에서 기존안보다 평균 비용이 낮은 후보는 없었다.

## 1. 수요 시나리오

RECV는 입고, PACK은 포장 출발지다. 기존 시뮬레이터가 시드별로 만든 요청 일정에서, 아래 90분 구간 안의 **대상 출발지 일반 요청 도착 시각만** 다시 배치했다. 90분 구간은 시뮬레이션의 480·840·1,200·1,560·1,920·2,280분에 각각 시작한다. 각 구간의 흐름별 요청 건수는 유지했고, 긴급 요청과 대상 밖 요청의 시각은 그대로 뒀다.

| 시나리오 | 대상 출발지 | 집중 구간 | 같은 90분 안의 나머지 |
|---|---|---|---|
| 평소 흐름 | 변경 없음 | 원래 요청 일정 | 원래 요청 일정 |
| 짧은 집중 | RECV | 처음 10분 동안 평소의 3배 속도로 도착하도록 배치 | 나머지 80분은 0.75배로 배치 |
| 장시간 집중 | RECV | 처음 40분 동안 1.5배로 배치 | 나머지 50분은 0.60배로 배치 |
| 두 구역 동시 집중 | RECV와 PACK | 두 출발지 모두 처음 40분 동안 1.5배로 배치 | 각 출발지의 나머지 50분은 0.60배로 배치 |

두 RECV 단독 시나리오는 평소 대비 20분치에 해당하는 기대 물량을 집중 시간대로 옮긴다. 1,200시드의 여섯 구간을 모두 합하면 평소 흐름, 짧은 집중, 장시간 집중은 각각 RECV 일반 요청 **408,301건**으로 같다. 첫 10분의 RECV 요청은 평소 45,685건에서 짧은 집중 136,836건으로 늘었다. 첫 40분은 평소 181,926건에서 장시간 집중 272,295건으로 늘었다. 동시 집중은 구역을 추가한 조건이라 RECV 단독과 영향 범위가 다르다. [입력 건수 검증](results/input_profiles.csv)

집중 조건은 가설을 비교하기 위해 만든 입력이다. 공식 과제의 난수 생성 방식과 구분하고, 공식 웹 점수의 대용으로 사용하지 않는다.

## 2. 배차 규칙과 비교 기준

차량은 19대, 대기 임계값은 4분으로 고정했다. 공차 65m 이하에서 출발지에 대기 요청이 쌓이면 긴급 여부를 먼저 비교하고, 같은 일반 요청 가지에서 `w > 4`분인 요청을 우선한다.

- **01 기존안과 02 가상안**을 비교하면, 기존 9개 규칙을 모두 살린 상태에서 대기 예외만 더한 효과를 볼 수 있다. 02는 논리상 10노드라 진단용이다.
- **03 대조안과 04 제출 가능안**은 원거리의 기존 긴급 규칙 한 자리를 똑같이 비웠다. 둘의 차이는 대기 요청이 **2건 이상**인 근거리 일반 분기에 4분 규칙을 넣었는지다.
- **05 대조안과 06 제출 가능안**도 같은 방식으로 비교하되, 기존 근거리 대기열 분기를 **3건 이상**으로 바꿨다. 이 변경은 대기가 정확히 2건인 긴급 요청의 경로도 바꾸므로, **05와 03**을 따로 비교해 대기열 기준을 옮긴 효과를 확인했다.

사전에 고정한 시드 43001–44200을 각 시나리오의 여섯 안에 똑같이 적용했다. 비용은 공식 목적함수와 같은 식으로 계산했다. 지연은 일반 요청이 8분 안에 픽업되지 않은 경우다. 아래 구역별 지표는 각 90분 구간의 **처음 60분에 들어온 대상 출발지 일반 요청 1,000건당** 지연 건수이며 시드별 값의 평균을 냈다. 평소 흐름은 같은 시간대의 RECV를 본다.

## 3. 1,200시드 짝비교 결과

| 시나리오 | 기존안의 대상 구역 8분 초과 지연 (1,000건당) | 02 가상 4분 예외의 지연 차이 (1,000건당) | 02의 총비용 차이 ± 표준오차 |
|---|---:|---:|---:|
| 평소 흐름 | 63.04 | −6.63 | +0.32 ± 0.36 |
| RECV 짧은 집중 | 189.21 | −7.92 | +0.93 ± 0.36 |
| RECV 장시간 집중 | 110.51 | −9.07 | +0.69 ± 0.34 |
| RECV·PACK 동시 집중 | 171.39 | −3.12 | +1.26 ± 0.35 |

비용은 천원/시간이고 차이는 후보에서 기준안을 뺀 값이다. 평소 흐름과 두 RECV 단독 조건은 같은 출발지를 관찰했다. 동시 집중의 대상 지연은 RECV·PACK을 합친 값이다. 가상 예외가 RECV 장시간 집중에서 지연을 더 많이 줄인 것처럼 보이지만, 같은 시드에서 짧은 집중과 효과 차이를 비교하면 **−1.15 ± 1.24건/1,000건**으로 뚜렷하게 구분되지 않는다.

**제출 형식의 결과.** 2건 기준인 04는 기존안보다 네 시나리오에서 **+1.57~+2.49점**, 3건 기준인 06은 **+4.29~+4.98점** 비쌌다. 예외 없이 대기열 기준만 2건에서 3건으로 바꾼 05도 03보다 평균 비용이 **+2.69~+3.75점** 늘었고, 긴급 픽업 P95가 약 **4.7~5.2초** 길어졌다. 원거리 규칙을 뺀 대조군끼리 비교한 값이다. 모든 평가에서 실격은 0건이었다.

**운영상 해석.** RECV에서 총 요청 수가 같아도 짧게 집중시키면 장시간 충격보다 기존안의 긴 지연이 더 많았다. 4분 예외는 이 지연을 줄였지만 비용 절감은 확인되지 않았다. 적체 기준을 더 높이는 방식은 긴급 서비스까지 바꿔 비용을 키웠으므로 현재 제출안에 적용하지 않는다.

## 4. 재현

저장소 루트에서 Visual Studio 개발자 PowerShell로 실행한다.

```powershell
cl /nologo /std:c++20 /O2 /EHsc /utf-8 agv_opt.cpp /Fe:agv_opt.exe
.\agv_opt.exe --yb-backlog-demand-profiles answer_final_best.csv q03-reproduced
.\agv_opt.exe --verify q03-reproduced/trees/04_q2_age4.csv
.\agv_opt.exe --verify q03-reproduced/trees/06_q3_age4.csv
```

변환을 적용한 12개 시드에서 구간별·흐름별 건수 보존과 비대상 요청 시각의 동일성을 확인했다. 각 시나리오의 첫 3개 시드에서 여섯 안의 빠른 계산과 전수 배차 쌍 계산의 비용이 일치했고, 실제 CSV 다섯 개는 제출 제약을 충족했다.
